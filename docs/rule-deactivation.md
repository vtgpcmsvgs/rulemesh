# 规则停用与恢复

停用是撤销当前配置中的规则功能，保留未来恢复所需的仓库资产。2026-09-12 的 AdsPower 停用作为后续同类任务的参考。

## 停用步骤

1. 确认适用客户端与配置范围，盘点规则调用、内联规则、观察兜底、专用 provider、DNS 例外及专用策略组；共享项先判断其他业务依赖。
2. 从授权范围内的当前配置移除对应调用和专用注册，同步公开模板。只删除功能专用项，不按名称顺带删除共享业务或机场手动组。
3. 保留 `rules/` 主清单、源规则、上游登记、构建逻辑和 `dist/` 产物；不得用清空源文件或删除产物代替停用配置。
4. 查询远程任务。独立专用定时任务暂停并保留定义；共用任务只暂停该功能专用步骤，不能停掉其他上游更新。通用构建继续生成保留资产，不算恢复客户端调用。
5. 更新当前行为文档和防回归检查，删除与本次停用相冲突的旧要求；检查全部对应配置中的残留调用、DNS 依赖和首条命中顺序。
6. 构建与全量检查通过后提交、推送公私仓库，分别报告远程同步与客户端运行态。重新启用需要用户明确要求，并重新验证依赖、规则顺序和 DNS 出口。

## 当前实例

- AdsPower：五份私有配置与两份公开模板移除 reject/direct/proxy 调用、Mihomo 专用 provider 和工作文件观察兜底。保留 `rules/app/adspower.txt`、三类源规则、登记、构建派生器和产物。
- 远程任务：本次查询公开仓库的三条 workflow 与私人仓库的空 workflow 清单，未发现 AdsPower 专用定时任务。通用上游同步及构建继续运行；未来维护需重新查询当时的远程状态。
- `check.myclientip.com` 是阿里云隧道共用出口探测入口，不在 AdsPower 主清单中，继续保留其精确直连。
- `direct/ips5_direct` 独立承接 `ips5.vip` 主域及所有子域，七份配置以 DIRECT 调用，位于 AI 之后、Google 广谱与拒绝之前；沿用国内双 DoH，不增加海外 DNS policy。不会把相似名称域名或节点 IP 纳入范围。
