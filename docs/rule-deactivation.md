# 规则停用、删除与恢复

停用是撤销当前配置中的规则功能，保留未来恢复所需的仓库资产。删除用于用户明确确认业务已不需要的情况，同时移除完整资产。AdsPower 已于 2026-10-23 从停用改为删除，旧保留约定不再适用。

## 停用步骤

1. 确认适用客户端与配置范围，盘点规则调用、内联规则、观察兜底、专用 provider、DNS 例外及专用策略组；共享项先判断其他业务依赖。
2. 从授权范围内的当前配置移除对应调用和专用注册，同步公开模板。只删除功能专用项，不按名称顺带删除共享业务或机场手动组。
3. 保留 `rules/` 主清单、源规则、上游登记、构建逻辑和 `dist/` 产物；不得用清空源文件或删除产物代替停用配置。
4. 查询远程任务。独立专用定时任务暂停并保留定义；共用任务只暂停该功能专用步骤，不能停掉其他上游更新。通用构建继续生成保留资产，不算恢复客户端调用。
5. 更新当前行为文档和防回归检查，删除与本次停用相冲突的旧要求；检查全部对应配置中的残留调用、DNS 依赖和首条命中顺序。
6. 构建与全量检查通过后提交、推送公私仓库，分别报告远程同步与客户端运行态。重新启用需要用户明确要求，并重新验证依赖、规则顺序和 DNS 出口。

## 当前实例

- Webshare：2026-10-23 删除住宅代理规则和 GFW 快照中的 `webshare.io`，GFW 上游同步同时排除该主域与子域，避免每天重新导入。其他住宅代理规则未经确认不删除。
- 本地仓库的三条 workflow 没有 AdsPower 专用步骤，通用同步和构建继续运行；本次远程任务状态未查询，不沿用旧查询结论。
- `check.myclientip.com` 是阿里云隧道共用出口探测入口，不在 AdsPower 主清单中，继续保留其精确直连。
- `direct/ips5_direct` 独立承接 `ips5.vip` 主域及所有子域，七份配置以 DIRECT 调用，位于 AI 之后、Google 广谱与拒绝之前；沿用国内双 DoH，不增加海外 DNS policy。不会把相似名称域名或节点 IP 纳入范围。

## 彻底删除步骤

1. 用户明确说明删除业务后，盘点源规则、上游登记、模板、构建派生器、检查与测试、私有配置、DNS 和任务依赖；共享项仍按实际用途保留。
2. 删除业务专用资产和生成入口，更新 `sources.yaml`、`merge.yaml` 与当前说明；通过正常构建移除产物，不手改 `dist/`。
3. 若域名来自定时更新的上游，在同步入口排除已撤销业务，测试真实同步路径及相似域名边界，避免更新后恢复或误伤其他域名。
4. 审计实际私有配置和 DNS 例外，未内联相关业务时无需改写客户端文件。移除规则后流量继续匹配其余规则；不等于新增 DIRECT、REJECT 或放行工作白名单。
5. 其他可疑资产只记录证据、现状和删除影响，等用户确认。构建、全量检查、文档与公私提交同步分别报告；静态检查不代表客户端加载或 DNS 出口实测。
