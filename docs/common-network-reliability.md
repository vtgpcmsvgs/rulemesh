# 常用业务连通性：2026-09-16

本次属于私人 FlClash 路由收敛、检查脚本和使用说明更新。公共源规则、上游登记、公开模板行为不变。实际私人目录是 `rulemesh-local` 根目录，没有创建 `current`。手机运行配置实际验证；桌面只同步源文件，不启动、重载或借用本机 FlClash。Surge 保留独立策略。

## 为什么常用应用也会失败

这些问题没有单一根因，现有证据应分层解释：

| 层次 | 已确认事实 | 含义 |
| --- | --- | --- |
| 分流策略 | 阿里系前置代理包含支付宝、淘宝、闲鱼、高德及共享资源；支付宝组件经原代理时部分 UDP 只有发送，直连对照有返回 | 常用国内业务被人为绕到海外，依赖机场 UDP、跨境回程与目标服务策略；热门程度不能抵消错误的出口选择 |
| 安卓接管 | 大智慧曾在界面关闭系统代理后，仍使用携带旧 HTTP 代理的活动 VPN；完整重建 VPN 后原页面恢复 | YAML 和保存值不足以代表系统运行态，属于客户端接管与验收问题 |
| 协议与应用 | 先前 Google 下载修复中的 UDP/443 拒绝导致 Cronet 协议错误及重试，撤销后整包下载通过 | “强制 TCP 更稳定”未经手机实测不成立，不能机械禁用 QUIC |
| 选择与健康检查 | Google 204 是小型 HTTPS 探测；最低延迟不能证明视频吞吐、UDP、登录或长连接可用 | 节点测速成功与业务可用必须分开，Google 继续使用已验证的稳定组 |
| 验收覆盖 | 曾只核对设置保存值、单页和单个组件；没有覆盖常用业务首条命中及共享进程 | 配置结构测试需要补充行为样本，仍不能替代客户端验收 |

这说明 RuleMesh 当前配置策略及验收方式确有需要修正的部分。没有证据表明规则构建流水线把文件生成错了，也不能把所有故障推给机场。第三方机场配置通常有较少的个性化规则与地区例外，因而可能更少引入此类冲突；本轮未取得用户当时的完整第三方配置，不能声称已经完成一对一比较。

YouTube 在移动数据、Wi-Fi 的常规复测中成功，但恢复移动数据并完整重建 VPN 后，明确出现过一次 `ERR_CONNECTION_CLOSED` 主文档失败；后续还捕获部分 QUIC 资源超时。保持配置不变刷新后恢复，不能为这次瞬时故障编造唯一根因，也不能把它从报告中删去。

## 本轮实际变更

用户明确选择“国内日常业务恢复直连，保留 AI、Crypto、日本入口、香港券商等明确地区要求”。据此：

- 两份 FlClash 删除 `hk_alibaba` 调用与专用 provider。源规则、上游登记和三条产物线继续保留，其他客户端不会被资产删除波及。阿里业务按照现有国内/目的地规则及 DIRECT 兜底处理，不将整个阿里云网络设成新的前置直连规则。
- 安卓撤下同日早先的三个支付宝 AND 组件例外，它们的用途已由正常直连覆盖。网页端和其他阿里应用同时受益，不再仅保护某个包名的三个主机。
- 安卓删除系统下载管理器及其界面的两条整体代理规则。共享进程按目的地分流：国内 CDN 直连，Google CDN 走 Google 稳定组，GitHub 走既有代理。Google Play、Google Play 服务和服务框架三个专属进程仍保留兜底。
- DNS、Fake IP、QUIC、机场源、策略组、最终 DIRECT 以及明确地区要求保持。没有清除用户应用数据或执行支付、交易、下单、发消息操作。

安卓有效规则由 73 条减至 67 条，桌面源由 65 条减至 64 条。桌面文件发布不等于桌面客户端已经加载或通过实机验收。

## 防回归检查

`tools/common_route_cases.json` 维护 67 个业务域名/进程样本。`tools/check_common_routes.py` 对每个样本分别检查 TCP、UDP 的首条命中，并从目标配置解析策略角色，避免硬编码私人策略组名。当前覆盖：

- Google、YouTube、Play、ChatGPT、Google AI、Telegram、GitHub、Wikipedia、Reddit、Discord、Instagram、Facebook、X。
- 支付宝、淘宝、闲鱼、高德、微信、抖音、小红书、豆包、元宝、京东、拼多多、滴滴、大智慧。
- 国内共享下载、Google 共享下载、GitHub 共享下载及 Crypto、日本入口、香港券商边界。

全量 `tools/check.ps1` 已接入此检查。首次审计中，安卓 116 个检查有 18 个与新直连目标不符，桌面有 24 个，均命中阿里系代理。调整后新增下载及海外样本，共 134 个检查/配置。样本默认目的端口为 443，行情等专有端口另需实机证据。脚本拒绝空用例、未知语法、未注册或不可核对的 provider；对没有真实 IP 的域名样本，不假造 GEOIP、ASN 或 IP 段运行结果。

此检查验证“配置应送往哪里”，不会发网络请求，也不能证明网站正在工作。源规则更新后仍要检查最终加载状态与业务；手机号、账户、消息、订阅地址和真实节点信息不写入报告。

`tools/check_browser_evidence.py` 将脱敏浏览器证据分为失败、未完成、局部资源失败、媒体未确认和通过。错误页即使含文字也不能通过；主文档错误不能被旧 DOM 掩盖；视频正在播放但脚本或样式报错仍算局部失败。配套测试覆盖此次 `chromewebdata` 错误页和 QUIC 子资源超时，避免诊断脚本的“文字长度大于零”假通过再次发生。

## 手机验收

本轮基于手机 FlClash 和真实应用连接。应用启动观察到返回流量，不等于支付、聊天发送、订单变化或所有深层组件已逐个验收；没有用这些操作扩大测试范围。

- 国内 11 个应用（支付宝、淘宝、闲鱼、抖音、小红书、豆包、元宝、京东、拼多多、微信、滴滴）均观察到新的 DIRECT 返回；当前可读界面未出现固定网络错误提示。支付宝“最近消息”显示；多个应用有 UDP 双向流量。
- Telegram 观察到代理返回；ChatGPT 观察到既有美国组相关业务返回。此轮包管理器未找到先前的大智慧包，只有其域名路由与 DNS 复核，不把历史实测冒充当前安装验收。
- 24 个代表域名的内核 DNS 查询均成功。连接表确认 AI 与 Google 的两个海外 DoH 各自经过正确组并有返回；国内 DoH 内部连接仍未被控制器独立暴露，国内 DNS 出口仅有有效配置证据，未完成独立抓包。
- 删除共享下载进程代理后，Play 完整下载并安装 VLC，33,081,623 字节，安装完成时间约 28.9 秒；该任务未捕获 `1404` 或 QUIC 错误。这是一次当前网络样本，不将与旧样本的耗时差写成稳定性能提升。

- 手机 Chrome 前台复测中，Google、Telegram、ChatGPT、Wikipedia、Reddit 均返回 HTTP 200 并完成文档加载；GitHub 主文档和正文返回，但 12 秒窗口结束时仍处于 interactive，未把它记录为全部资源完成。YouTube 在移动数据和 Wi-Fi 下都重新刷新成功，视频预览 readyState 为 4、播放时间前进、没有媒体错误；独立 YouTube 复测未捕获未取消的网络错误。

## 恢复与边界

保留旧选中配置和完整备份作为回滚；本轮新配置采用独立名称，最终导出完整备份。恢复备份或更改 VPN 选项后，须完整停止并启动 VPN，运行 `tools/check_android_vpn_runtime.py --adb <实际路径>`，再检查真实页面。

最终兜底仍为用户此前选择的 DIRECT：未被代理规则覆盖的受限海外服务可能直连失败。不能在缺乏证据时把所有未知流量自动送海外；新增高频服务应登记代表业务域名与真实请求证据，再决定规则。机场故障、服务器拒绝特定出口、登录验证和运营商网络变化不由规则文件单独控制，必须与分流错误区分。

诊断脚本对动画页面的 UiAutomator 失败保留网络证据并标记界面未知；Android Chrome 不支持桌面式 `/json/new` 时，使用标准浏览意图创建标签，并核对新的实际标签 ID。VPN 起停后按钮宽度可能改变，须读取新布局再定位；控件类型、中文端口边界和多文件补丁锚点均先检查，不把自动化命令失败当作业务网络失败。

备份文件选择器的标题不代表完整保存路径。一次按标题推断路径导致拉取失败，改为确认“备份成功”、在授权下载目录查找唯一目标后拉取并验证；拉取失败必须立即中止后续验证，不能把后续文件不存在误报成备份内容损坏。包含 SQL 等嵌套引号的临时诊断写入任务脚本文件执行，避免多层 shell 转义破坏命令。

FlClash 的 `/proxies` 可能只列策略组，provider 节点需要从实际控制器的 `/providers/proxies` 读取并关联。不能因选中节点不在前一个返回中，就判定节点缺失或失效；节点存活还要同时检查 `alive`、非空健康历史、正延迟与时间新鲜度。
