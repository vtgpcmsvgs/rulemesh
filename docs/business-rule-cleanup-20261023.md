# 2026-10-23 业务规则清理

以用户最后确认的业务边界为准：Webshare 网站仍在使用，购买的代理 IP 与链式拨号能力已不需要。网站规则不能与代理端点一起删除。

| 业务 | 当前处理 |
| --- | --- |
| Webshare 网站与其他 24 个住宅代理网站域名 | 保留住宅代理入口；恢复 webshare.io 与 GFW 覆盖，撤销同步过滤 |
| AdsPower | 删除主清单、三类源规则、登记、派生器和构建产物 |
| ips5.vip 专项直连 | 删除源规则、登记、客户端调用与产物，后续按其余规则处理 |
| 香港、东京、大阪、首尔、台北 AWS IPv4 | 删除五份入口、快照、同步任务、构建自举与专项文档 |
| 链式 SOCKS5 | 删除公开端点快照、登记、产物，以及私有内联节点、负载均衡组和指向该组的拨号引用 |
| 阿里系强制代理 | 删除专用规则与 Alibaba/Xianyu 专用快照及同步项；保留阿里云 SSH 直连与共享国内规则 |
| 1Password | 官方域名继续更新，纳入 proxy/general_proxy，不再注册独立 provider 或调用 |
| Polygon / BSC RPC | Chainlist 快照继续更新，合并进 region/tw/crypto_tw，沿用台湾出口 |

`proxy/general_proxy` 复用 GitHub 核心 HTTPS 与官方 1Password 快照，使用既有通用自动选择。工作配置只显式放行该有限范围，不接入 GFW 广谱，保留 GitHub SSH、Raw 自举、观察规则与 FINAL,REJECT。机场手动组和各地区自动组继续保留。

普通业务仍使用默认国内 DNS，AI 使用美国出口与专用解析；本次没有新增 DNS 例外。公开示例、私有 Surge、FlClash 与派生 iOS 配置同步维护。静态规则与 DNS 检查不能证明客户端已加载，也不能代替实际设备出口验收。

## 审计与防复发

- 原审计误把 Webshare 网站等同于购买的代理端点。恢复网站与真实 GFW 同步路径的正向测试，并核对其余 24 个网站保留。
- 只看 RULE-SET 调用图会漏掉节点拨号。实际配置仍有内联 SOCKS5 节点、负载均衡池及自动测速组的 dialer-proxy。删除业务时须遍历节点、策略组成员、dialer-proxy / underlying-proxy、provider、DNS 与生成器，不能凭“没有规则调用”判定完全停用。
- 源规则合并须验证编译后保留全部官方快照规则；不能以“移除专用入口”代替保留业务覆盖。回归测试覆盖 1Password、GitHub、Webshare 及 RPC 正向路由。
- 首轮路由验证误用了当前快照中不存在的旧 BSC 接口名称；样本改用快照中的 bsc-dataseed.bnbchain.org，并增加样本必须属于当前快照的检查。不能凭历史接口名称猜测覆盖范围。
- 全仓清理必须区分业务资产与共享基础设施：阿里云 SSH、普通 AWS 服务域名、完整 cn_direct / gfw 兼容入口不属于本次删除范围。
- 用户确认另有任务并行维护订阅检查及订阅地址。审计须按字段区分来源，提交按变更块隔离，不把整文件的其他任务改动一并暂存。
- 跨任务检索也可能返回私人地址、凭据和原始工具命令；只在内存中提取授权与进度，脱敏后输出必要字段，不直接回显原始读取结果。
- PowerShell 的 rg 命令把全部选项放在 -- 之前；零命中按预期退出码处理，失败后停止依赖步骤。迁移和文档更新先预检唯一锚点，避免重复段落误替换。
