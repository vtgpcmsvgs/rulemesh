# 安卓 FlClash 网络与 Google Play 下载修复

2026-09-14 用户报告安卓 Google/YouTube 网页不可达、Play 商店可浏览但下载反复转圈、大智慧行情/K 线空白及滴滴订单状态更新延迟，并授权优先修复下载稳定性。本次对安卓配置实施专项保护；桌面和 Surge 不自动继承这一例外。

## 已确认与尚未确认

- 现有 `region/hk/google_hk` 已包含 Google、FCM、YouTube、`gvt1/2/3`、`googleusercontent`、下载重定向域名及官方 IP 地址空间。重复添加同一域名不能解决进程接管或传输问题。
- 原安卓配置没有 Play、服务框架和系统下载管理器的进程兜底；普通 Google 使用最低延迟自动组，且没有专用 DNS policy。`android.clients.google.com`、`clients4.google.com` 曾被混入联网探测的 Fake IP 排除表。
- 已知大智慧、滴滴业务域名没有命中当前广告或系统更新拒绝表；这不等于真实失败请求全部直连。必须区分域名、硬编码 IP、行情专有协议和后台运行限制。
- ADB 已连接 Android 14、FlClash 0.8.97；未发现自定义私人 DNS。通过应用自己的备份读取到标准模式、DNS 覆写关闭、全应用 VPN、进程识别 `always`；原导入文件与当时私有源逐字节一致。正式版私有目录不能使用 `run-as`，没有绕过应用沙箱。
- 第一版下载保护新增的 UDP/443 拒绝不适用于这台手机：实测出现 `ERR_QUIC_PROTOCOL_ERROR`、Play 安装任务 `1404`、约 100 秒等待，以及主体完成但最后 275 KB 分包没有进度。手机当前 Play 版本中的错误映射表明 `1404` 对应 Volley `NetworkError`，并不等于某个 HTTP 状态码，也不能单凭它认定唯一根因。曾另观察到 `play.googleapis.com` 超时。
- 清理 Play 缓存后一次下载迅速完成，但重复安装仍失败；切换另一条健康线路也复现，因此不能把清缓存或 204 测速通过当成彻底修复。撤销六条 UDP/443 拒绝后，实机连续三个完整下载首次成功，观察到前置 API 与下载 CDN 的 QUIC 双向数据。

## Google Play 与网页的配置保护

仅 `rulemesh-substore-mihomo-flclash-android.yaml` 使用带日期标记的例外：

1. `hk_google` 使用独立 `fallback` 组。直接纳入全部当前机场节点，沿用套餐占位过滤；每 600 秒主动检查。按节点顺序选择可用节点，避免为追逐更低延迟而周期性换出口。故障切换仍可能换 IP；204 成功也不代表下载吞吐合格。
2. Play、Google Play 服务、服务框架、下载管理器及其界面五个包名使用同一组兜底。进程规则位于 Google 域名入口之后、广告拒绝之前。系统下载管理器也会替其他应用下载，因此这些共享下载会经过代理；这是本次稳定性优先的明确取舍。
3. 保留 Google/Play QUIC。已撤销第一版针对 Google 规则集和五个进程的六条 UDP/443 拒绝，规则数从 76 变为 70。Cronet 没有可靠回退，不能用 `REJECT`、`REJECT-DROP` 或稳定组 `disable-udp` 强制 TCP；让客户端根据连接能力选择 QUIC 或 TCP，并检查节点真实 UDP 返回流量。
4. `nameserver-policy` 先 `us_ai`，后 `hk_google`；后者的 Cloudflare/Google DoH 都通过 Google 稳定组。AI 的美国 DNS 与第一条美国规则继续保留。普通国内解析与节点 bootstrap 仍是国内双 DoH，不开启 `respect-rules`，不引入 DNS `fallback` 或第二层节点 policy。
5. 从 `fake-ip-filter` 移除两个被误归类的 Play API 主机，保留真正的联网探测、局域网例外与全局 Fake IP。Google DNS 查询和下载连接分别检查，不能仅以网页成功替代 DNS 出口证据。

运行态 DNS 复测：导入后 AI 查询曾出现超时，重建 VPN 后 `chatgpt.com` 与 `play.googleapis.com` 均返回成功；同时观察到 Cloudflare/Google DoH 分别经过 AI 美国组和 Google 稳定组。大智慧、滴滴域名查询也成功，但控制器连接列表没有暴露内核的国内 DoH 直连套接字，国内 DNS 出口仍以有效配置为证，未完成独立抓包确认。ADB 的启动命令曾超时，实际 VPN 随后恢复；验收以恢复后的查询与连接为准，不能把命令超时写成操作成功。

FlClash 0.8.97 源码默认：标准模式、DNS 覆写关闭、进程识别 `always`、VPN 开启、应用访问控制关闭、VPN 系统代理开启、允许绕过开启、全端口 DNS 劫持关闭。本机已从备份核对这些值，并实际修改为：系统代理关闭、允许应用绕过关闭、DNS 劫持开启；VPN、全应用接管、IPv6 关闭及进程识别继续保留。第一次验收只核对了保存值，随后用户反馈大智慧仍有空白组件；系统层发现旧 VPN HTTP 代理仍存在。完整停止并启动 VPN 后，才确认实际移除，详见下文补充验收。

这些是客户端设置，不能靠修改 YAML 的桌面 TUN 字段宣称已经完成。换手机、清除 FlClash 数据或重装后，应重新核对。浏览器若另外设置了自定义安全 DNS，须单独检查其解析路径，不能把 HTTP 状态错误都归因于 DNS。

## 大智慧与滴滴的处理方案

- Google/YouTube 网页：Chrome 普通 Google 首页、搜索结果及 YouTube 首页均加载。最初 Google 返回 `/m` 的 HTTP 404，访问 `/ncr` 后普通入口恢复；这是服务端已返回页面，不能记录成 DNS 或 TCP 不通。没有清除 Chrome 全部数据。
- 大智慧：首轮曾观察到单只股票分时和日 K 加载，但用户随后确认多个组件仍无数据，首轮结果不能作为整体验收。补充复测捕获空白报价及行情连接错误，并发现运行中的 VPN 仍发布旧 HTTP 代理；完整停止、启动 VPN 后同页恢复，重开应用后多个股票、自选曲线、日 K 与行情总览均加载。继续保留既有源规则与 Fake IP，未新增未经证实的域名或应用绕过项。
- 滴滴：确认包名 `com.sdu.didi.psnger`；历史订单页面已加载，主要业务请求和 TCP/25641 长连接为 DIRECT 且有返回。系统 `RUN_ANY_IN_BACKGROUND` 为允许，但这不覆盖所有厂商省电机制。没有可复现的真实行程结束事件，订单即时更新与长期后台推送仍未验收；没有创建、支付或改变任何订单。
- Mac Surge 当前没有用户确认的同类故障；本次下载例外只在安卓启用。Surge 的域名覆盖已随共用资产检查，但未连接 Mac 验证运行时，不能称其运行态完全正常。

### 大智慧补充验收：保存值与实际 VPN 不一致

用户确认 Google、YouTube 和 Play 已恢复，但大智慧“有的组件有网、有的没网”。同一时刻的证据为：界面和备份中的 `vpnProps.systemProxy` 均为 `false`，Android 活动 FlClash VPN 的 `LinkProperties` 却仍带回环 HTTP 代理。大智慧部分连接进入 HTTP/HTTPS 代理入口，行情 TCP/12346 反复没有返回，并出现关联的 `dns resolve failed`；其他资讯与广告连接已直连成功，因此不能用“应用已有返回流量”判定全部恢复。

这次保持 YAML、Fake IP、DNS policy 和分流规则不变，在 FlClash 仪表盘完整停止 VPN，再启动。Android 系统层确认新的活动 VPN 已没有 `HttpProxy`，同一空白页面恢复报价、分时、五档、成交量与日 K；TCP/12345 从 Tun 入口 DIRECT 返回数据。再强制结束并重开大智慧，多个原先为空的自选报价、迷你曲线和行情总览均恢复，期间没有再次捕获大智慧的 DNS 错误。没有清除应用数据、修改自选或执行交易。

DNS 复测中，`chatgpt.com`、`play.googleapis.com`、`www.gw.com.cn`、`dsp.dzh.com.cn` 均成功；AI/Google 的 DoH 仍分别经过既定美国组/稳定组。国内 DNS 出口仍保留前述独立抓包限制。此轮活动 VPN 的底层为移动数据，不能把系统历史中的 Wi-Fi 条目当成当前网络。

完整重建 VPN 后还追加一次 Play 回归：VLC 完整下载 33,081,623 字节并安装成功，`attempt=0`，安装完成时间 71.232 秒，未捕获 `1404` 或 `ERR_QUIC_*`。这一次样本与前一轮三次下载分开记录，确认真正移除 VPN HTTP 代理后下载仍可完成。

迁移、恢复备份或修改 VPN 开关后，必须完整停止并启动 FlClash VPN，再检查系统运行态；只关闭应用窗口、导入 YAML 或看到开关为关闭都不足以验收。新增只读工具 `tools/check_android_vpn_runtime.py --adb <adb.exe 的实际路径>`：读取唯一 USB 设备，确认活动 VPN 归属 FlClash 且不带 HTTP 代理；输出仅计数、布尔值和错误类型。它不修改手机，不替代 DNS 出口和业务验收，也不自动加入无人连接手机时的构建流程。

解析器测试覆盖 `CELLULAR|VPN`、`WIFI|VPN`、历史记录、其他 VPN、断开状态、残留代理和未知字段格式。运行态无法唯一确认时失败，不把缺失证据写成开关已生效。

## 验收、回滚与证据边界

前一版静态检查没有发现 Cronet 的实机兼容问题。修订版增加拒绝 QUIC 的防回归用例，三份 Mihomo 通过原生 YAML 校验；全量 266 项测试中 251 项通过、15 项按环境跳过，50 份源规则构建且 0 条构建 warning。静态通过不能代替手机验收。

隔离内核曾完成三次 8 MiB 字节段下载，但未覆盖安卓 Cronet，不能作为最终验收。2026-09-14 晚间保留 QUIC 的手机配置，在移动数据下顺序完成以下三次从下载到安装的实测；三次都是 `attempt=0`，采集期间未出现 `1404` 或 `ERR_QUIC_*`：

| 应用 | 完整下载字节 | 开始下载 | 安装完成 |
| --- | ---: | ---: | ---: |
| Firefox | 89,650,327 | 2.756 秒 | 140.300 秒 |
| VLC | 33,081,623 | 6.491 秒 | 74.190 秒 |
| Google Earth | 28,288,662 | 10.502 秒 | 74.485 秒 |

总量 151,020,612 字节，约 144.0 MiB；计时取自 Play 当前安装任务的状态日志，完成由包管理器交叉核对。观察到 Google 前置 API、图片服务和下载 CDN 的 UDP/443 双向数据，也有 TCP 下载；不将“保留 QUIC”写成“所有请求必须使用 QUIC”。这些样本证明当前网络和线路可完成整包下载，不能保证机场、运营商、Google 服务或今后的网络切换永不失败。

收尾从 FlClash 导出最终备份，确认只保留一个选中的标准模式配置，70 条规则及解析后的 YAML 与私有源一致；注释差异不计作路由差异。再次核对全应用 VPN、系统代理关闭、绕过关闭、DNS 劫持开启、IPv6 与 DNS 覆写关闭、进程识别 `always`。临时控制器已关闭、日志恢复 `error`、ADB 诊断转发已移除；三个临时测试应用已卸载。原始备份保留，最终备份与源 YAML 放在手机 `Download/RuleMesh`，移除旧导入配置，避免误选。

换网络验收应覆盖 Wi-Fi 与移动数据；本轮已确认的是移动数据，Wi-Fi 未测试时必须明确保留缺口。不要把首页、204、小文件或隔离内核成功当成安卓大文件验收。遇到“等待 Wi-Fi”、待处理队列、空间不足或下载管理器被停用，分别按显示状态处理。测试安装只点击目标应用的主安装按钮：先确认该包未安装、页面标题匹配，已有“打开/卸载”时禁止点击推荐或其他设备的安装按钮。

更新配置并重启 FlClash VPN 后，取消既有卡住任务并重试；必要时只清理 Play 商店缓存。不要默认清除 Google 服务框架或下载管理器数据，那会影响登录、设备注册或其他下载队列。无法取得手机运行信息或下载样本时，明确报告“配置已加固，实机下载未验收”，不能承诺永不复发。

私人配置修改前保留字节备份，回滚时只恢复安卓文件与本次实际改动的界面开关，重新更新订阅并验证。私有仓库推送成功代表分发源更新，不代表安卓已刷新。

`tools/check_android_stability.py` 接入全量检查；测试防止遗漏进程、恢复 Google/Play QUIC 拒绝、全局 UDP 拒绝、Google DNS 抢占 AI、稳定组变回测速组，以及例外扩散到桌面。现有 Google 下载域名直接从源规则编译后验证，不另建重复 Play 规则集。

## 本次诊断经验

- 症状：调用旧解析器未提供的测速字段、向构建器传相对路径、从业务简称猜测第三方路径，造成诊断命令失败。根因是未先核对 API/文件清单。修复为使用测速专用解析器、绝对源路径及已枚举的源码路径；后续脚本在写入前进行完整内存预检，任何失败立即退出。
- 症状：旧 DNS 禁用说明在配置顶部和 DNS 节各存在一次，单一数量假设不成立。修复为逐一核对全部位置再替换；新检查禁止安卓重新出现会诱发删除已批准 policy/bootstrap 的说明。
- 症状：安卓已授权 ADB 读取，但点击被 `INJECT_EVENTS` 拒绝。需要用户开启设备自己的 USB 调试安全设置或手动操作，不能将普通调试授权等同于点击授权。正式版 `run-as` 失败是系统权限边界，不修改应用或绕过沙箱。
- 诊断 UI 可能同时显示内网地址、订阅和节点；默认输出固定界面词、字段名、布尔值与计数。连接/API 原始结果只在内存解析，不输出 URL 查询、节点、密钥、订单或账号内容。
- 隔离 FlClashCore 的 `setupConfig` 可加载 DNS/API，但不代表已启动业务代理监听。首轮下载样本因未调用 `startListener` 而连接失败，不能记为线路故障；修复探针后先断言配置中的本地代理端口可连接，再测下载。对已运行手机只读取其实际配置，不猜测控制端口。
- 静态规则正确不代表 Cronet 一定回退 TCP；本次实机失败促成撤销 QUIC 拒绝，并将“拒绝必须存在”的旧检查反转成“拒绝不得恢复”。清缓存、换节点和最终协议调整的样本分开记录，不合并成一次成功。
- Android 控件、包查询与 API 均先核对实际语义：搜索框可能是 `AutoCompleteTextView`；`pm path` 对未安装包可返回非零，安装前改用包列表确认；FlClash 此版本 HTTP 控制器仅支持 GET，不能假定标准 Mihomo 的 PATCH 可用。`pm clear --cache-only` 曾超时，后通过系统 UI 确认清缓存，不能把超时当成功。
- UI 操作前重新核对目标身份；页面变化时停止点击。上轮误点其他设备的安装入口后，本轮确认其显示失败重试且本机无额外安装，并增加目标包、标题和主按钮位置保护。ADB 点击授权与正常 USB 读取授权分别验证。
- 诊断采集设置时限、停止标记与更新时间；采集结束或失败后不再把旧文件当实时结果。安装日志按时间和任务重试分开记录，不能按状态全局去重后把后一次下载误当首次。并发 DNS 探测逐项保留成功和错误，禁止一个异常吞掉其他结果。
- 全仓复核发现 README 仍引用旧分层 DNS 白名单并混淆 DNS `fallback` 与代理组 `type: fallback`，已替换为现行基线和安卓窄例外；检查和维护时必须按字段所属节判断，避免旧说明诱发回滚。
- DocumentsUI 的面包屑包含 Download，不代表当前就在该目录根部；导出后应先确认成功提示和实际文件位置，再读取备份。收尾用唯一文件名定位、校验 ZIP 与文件哈希后复制到明确的任务目录，避免把路径错误误判为导出失败。
- 补充复测纠正了“保存值等于生效值”的错误假设：VPN 开关变更必须通过完整停止/启动和系统 `LinkProperties` 验收；传输可能为 `CELLULAR|VPN`，不能只搜索固定字符串 `Transports: VPN`。这两项已写入只读检查器与回归测试。
- ADB 启动应用先解析当前 launcher activity；自绘图表标签可能不在 UI 文本树中，应以当前截图确定位置。截图生成命令返回运行中会话时，必须等其成功退出后再读取文件，不能把尚未生成误报为丢失。
