# 安卓 FlClash 网络与 Google Play 下载修复

2026-09-14 用户报告安卓 Google/YouTube 网页不可达、Play 商店可浏览但下载反复转圈、大智慧行情/K 线空白及滴滴订单状态更新延迟，并授权优先修复下载稳定性。本次对安卓配置实施专项保护；桌面和 Surge 不自动继承这一例外。

## 已确认与尚未确认

- 现有 `region/hk/google_hk` 已包含 Google、FCM、YouTube、`gvt1/2/3`、`googleusercontent`、下载重定向域名及官方 IP 地址空间。重复添加同一域名不能解决进程接管或传输问题。
- 原安卓配置没有 Play、服务框架和系统下载管理器的进程兜底；普通 Google 使用最低延迟自动组，且没有专用 DNS policy。`android.clients.google.com`、`clients4.google.com` 曾被混入联网探测的 Fake IP 排除表。
- 已知大智慧、滴滴业务域名没有命中当前广告或系统更新拒绝表；这不等于真实失败请求全部直连。必须区分域名、硬编码 IP、行情专有协议和后台运行限制。
- ADB 已连接 Android 14、FlClash 0.8.97；未发现自定义私人 DNS。首次观察没有已运行的 FlClash 服务，因此还不能用这次观察解释故障发生时的路径。正式版应用私有目录无法用 `run-as` 读取。

## Google Play 与网页的配置保护

仅 `rulemesh-substore-mihomo-flclash-android.yaml` 使用带日期标记的例外：

1. `hk_google` 使用独立 `fallback` 组。直接纳入全部当前机场节点，沿用套餐占位过滤；每 600 秒主动检查。按节点顺序选择可用节点，避免为追逐更低延迟而周期性换出口。故障切换仍可能换 IP；204 成功也不代表下载吞吐合格。
2. Play、Google Play 服务、服务框架、下载管理器及其界面五个包名使用同一组兜底。进程规则位于 Google 域名入口之后、广告拒绝之前。系统下载管理器也会替其他应用下载，因此这些共享下载会经过代理；这是本次稳定性优先的明确取舍。
3. 仅对 Google 规则集和上述进程的 UDP/443 设置 `AND … REJECT`，位于 Google 放行前，促使支持回退的 HTTP/3 客户端改用 TCP。不是全局禁 UDP，不使用静默 `REJECT-DROP`，也不使用会导致不支持 UDP 的节点跳过当前规则的 `disable-udp` 代替拒绝。
4. `nameserver-policy` 先 `us_ai`，后 `hk_google`；后者的 Cloudflare/Google DoH 都通过 Google 稳定组。AI 的美国 DNS 与第一条美国规则继续保留。普通国内解析与节点 bootstrap 仍是国内双 DoH，不开启 `respect-rules`，不引入 DNS `fallback` 或第二层节点 policy。
5. 从 `fake-ip-filter` 移除两个被误归类的 Play API 主机，保留真正的联网探测、局域网例外与全局 Fake IP。Google DNS 查询和下载连接分别检查，不能仅以网页成功替代 DNS 出口证据。

FlClash 0.8.97 源码默认：标准模式、DNS 覆写关闭、进程识别 `always`、VPN 开启、应用访问控制关闭、VPN 系统代理开启、允许绕过开启、全端口 DNS 劫持关闭。默认值不是手机当前运行值；更新后核对导入文件、最终配置及界面覆写。

若实机连接显示应用绕过 VPN 或浏览器仅走系统 HTTP 代理，应在安卓 VPN 设置关闭“系统代理”和“允许绕过”，启用 DNS 劫持，保留全应用 VPN 接管；这些是客户端设置，不能靠修改 YAML 的桌面 TUN 字段宣称已经完成。浏览器启用自己的安全 DNS 时，先关闭其自定义 DNS 再做对照，避免绕过 Mihomo 的域名映射。

## 大智慧与滴滴的处理方案

- 大智慧：在行情页刷新时只观察该应用失败连接，记录目标域名/公开端口、规则、DIRECT/代理、DNS 结果类型和错误类别。优先确认 `gw.com.cn`、`dzh.com.cn` 及实际行情域名；若确认是 Fake IP 或嗅探兼容问题，对这些实际主机设置真实国内 DNS 与嗅探例外，并将其精确直连放在 Google IP 规则前。直接连接硬编码 IP 时，通过实际包名或精确服务 IP 处理，不能猜测包名、广泛放行证券域名或禁用所有 Fake IP。
- 滴滴：先看订单状态查询/长连接是否经过代理或失败；实际安装包为 `com.sdu.didi.psnger`。可针对该包和确认的 `didichuxing.com`、`diditaxi.com.cn`、`xiaojukeji.com` 等业务入口前置直连。若前台正常、后台恢复才更新，继续检查后台数据、电池限制和推送连接；不把 Android 后台挂起错误归因于规则。复测使用已有订单，不创建行程、不改订单状态。
- Mac Surge 当前没有用户确认的同类故障；本次下载例外只在安卓启用。Surge 的域名覆盖已随共用资产检查，但未连接 Mac 验证运行时，不能称其运行态完全正常。

## 验收、回滚与证据边界

本轮已完成全量 265 项测试（250 项通过、15 项按环境跳过）、50 份源规则构建且 0 条构建 warning；三份 Mihomo 通过原生 YAML 校验，安卓配置通过隔离完整加载。隔离环境的七个国内/Google/AI DNS 查询成功，观察到 Google DoH 使用稳定组、AI DoH 使用美国组；国内 DoH 内部直连未出现在连接列表，不能据此宣称独立观察到了其生产出口。

隔离内核通过 Google 下载重定向 CDN 连续完成三次 8 MiB 字节段下载，均为 HTTP 206、ZIP 数据，耗时约 2.86/4.39/5.69 秒，期间稳定组选中节点未变化。样本合计 24 MiB，验证了重定向后的下载路径；不等于完整 APK 安装或安卓 VPN/进程规则已完成实机验收。手机点击安全授权、运行配置读取与真实 Play 下载仍需完成。

下载验收需要实机连续完成至少三次应用下载/更新，包含较大的应用；记录首次出现进度所需时间、持续字节增长、完成结果及重定向后的域名/出口。Wi-Fi 与移动数据各测一轮。不要把首页、204 测速、小文件或桌面隔离内核的成功当成安卓大文件下载已经修好。遇到“等待 Wi-Fi”、待处理更新队列、空间不足或下载管理器被停用，分别按显示状态处理。

更新配置并重启 FlClash VPN 后，取消既有卡住任务并重试；必要时只清理 Play 商店缓存。不要默认清除 Google 服务框架或下载管理器数据，那会影响登录、设备注册或其他下载队列。无法取得手机运行信息或下载样本时，明确报告“配置已加固，实机下载未验收”，不能承诺永不复发。

私人配置修改前保留字节备份，回滚时只恢复安卓文件与本次实际改动的界面开关，重新更新订阅并验证。私有仓库推送成功代表分发源更新，不代表安卓已刷新。

`tools/check_android_stability.py` 接入全量检查；测试防止遗漏进程、QUIC 规则放错位置、静默丢弃、全局 UDP 拒绝、Google DNS 抢占 AI、稳定组变回测速组，以及例外扩散到桌面。现有 Google 下载域名直接从源规则编译后验证，不另建重复 Play 规则集。

## 本次诊断经验

- 症状：调用旧解析器未提供的测速字段、向构建器传相对路径、从业务简称猜测第三方路径，造成诊断命令失败。根因是未先核对 API/文件清单。修复为使用测速专用解析器、绝对源路径及已枚举的源码路径；后续脚本在写入前进行完整内存预检，任何失败立即退出。
- 症状：旧 DNS 禁用说明在配置顶部和 DNS 节各存在一次，单一数量假设不成立。修复为逐一核对全部位置再替换；新检查禁止安卓重新出现会诱发删除已批准 policy/bootstrap 的说明。
- 症状：安卓已授权 ADB 读取，但点击被 `INJECT_EVENTS` 拒绝。需要用户开启设备自己的 USB 调试安全设置或手动操作，不能将普通调试授权等同于点击授权。正式版 `run-as` 失败是系统权限边界，不修改应用或绕过沙箱。
- 诊断 UI 可能同时显示内网地址、订阅和节点；默认输出固定界面词、字段名、布尔值与计数。连接/API 原始结果只在内存解析，不输出 URL 查询、节点、密钥、订单或账号内容。
- 隔离 FlClashCore 的 `setupConfig` 可加载 DNS/API，但不代表已启动业务代理监听。首轮下载样本因未调用 `startListener` 而连接失败，不能记为线路故障；修复探针后先断言配置中的本地代理端口可连接，再测下载。对已运行手机只读取其实际配置，不猜测控制端口。
